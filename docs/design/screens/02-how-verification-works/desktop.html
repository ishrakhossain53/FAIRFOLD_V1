What counts as evidence

Every verified credential maps strictly to inspectable code characteristics with capped ceiling weights.

Evidence Vector Max Weight Signal Impact Audit Criteria & Verification Rule
Source files authored using the skill
Up to +0.50 Strong Authentic source files (.ts, .jsx, .py, etc.) written by the candidate demonstrating active application of framework modules and idioms.
Commits authored by candidate
Up to +0.20 Medium Commits signed or authored under the candidate's verified Git email address matching their registered developer identity across commit trees.
Dependency manifest entry
Up to +0.15 Baseline Listed inside package.json, requirements.txt, or go.mod. Never qualifies a skill on its own without authored files.
Recency of activity
Up to +0.10 Boost Continuous commit cadence and authored files pushed within the last 6 to 12 months, reflecting contemporary framework familiarity.
Multi-repository breadth
Up to +0.05 Boost Skill demonstrates versatility by appearing across multiple distinct projects, decoupled architectures, or separate organizations.

What we ignore & down-weight

To prevent vanity metric inflation and resume spoofing, FairFold enforces automated heuristics that neutralize common portfolio tricks.

fork_right

Forks Without Original Commits

Forked upstream repositories are completely ignored by the AST crawler unless the candidate authored distinct merged commits or distinct upstream pull requests.

cancel Ignored (0.00)
content_copy

Copied Tutorials & Templates

Standard scaffoldings (e.g., unmodified create-react-app, cookiecutters, or hello-world walkthroughs) are flagged by code fingerprinting and deducted.

trending_down Down-weighted
folder_delete

Trivial or Empty Repositories

Projects containing zero unit tests, single markdown files, or trivial scripts failing minimum file counts and cyclomatic complexity gates are filtered out before evaluation.

Credential Standards

The Three Verification Statuses

Candidates and recruiters encounter three crystalline status states across FairFold scorecards.

check_circle Verified Score ≥ 0.60

Verified Competency

Full algorithmic confirmation. The candidate demonstrates original, syntactically substantial source code authored in public repos with recent commit frequency.

Recruiter Visibility Public / Searchable

Includes interactive code inspect links and commit hashes accessible to hiring teams with candidate consent.

schedule Partial Score 0.30 - 0.59

Partial Evidence

Identified in dependency files or sparse commit logs, but lacks broad multi-file authorship or recent project activity.

Recruiter Visibility Hidden by Default

Candidates can toggle visibility manually if they wish to accompany the skill with private portfolio references.

info Not Verified Score < 0.30

Unproven Claim

Skill declared on resume or profile without discernible public repository code footprint or verifiable commit history.

Recruiter Visibility Candidate Only

Provides private diagnostic tips indicating which repositories or commits could be shared to achieve verified status.

warning Algorithmic Integrity

Our system limits: What FairFold does and doesn't measure

We prioritize transparency over exaggerated promises. FairFold does not compute an all-knowing genius quotient—we verify physical code occurrences.

domain_verification Code Presence ≠ Seniority

FairFold proves that code exists and was authored by you. It does not evaluate subtle architectural trade-offs, managerial mentorship, or cultural alignment.

lock Proprietary IP Stays Secret

Engineers working inside closed enterprises are never asked to expose private employer code. We only audit what is deliberately public.

psychology Non-GitHub Skills

System design, SQL database tuning, production incident debugging, and team leadership seldom leave GitHub traces. We advise assessing these in interviews.
